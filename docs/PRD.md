# PRD: Poizon Bidding (포이즌 입찰 자동화 시스템)

> 버전: 0.3 (최근 업데이트: 2026-06-15)

> 작성일: 2026-06-15  
> 작성자: 안티그래비티 (문지영 대비마마 교시 반영)

---

## 1. 개요 (Overview)

포이즌(POIZON) Open Platform API를 활용하여, 리셀러가 **최적의 상품을 선택하고 네이버 최저가와 비교하여 수익성 있는 입찰을 자동화**할 수 있는 프리미엄 입찰 관리 도구.

---

## 2. 핵심 문제 (Problem Statement)

리셀러가 수익성 있는 입찰을 하려면:
1. 포이즌에서 현재 입찰 가능한 상품/가격 정보를 확인해야 함
2. 동시에 네이버 가격비교에서 해당 상품의 시중 최저가(매입원가)를 확인해야 함
3. 이 두 가지 데이터를 비교해 **수익이 남는 상품에만 입찰**해야 함
4. **불필요한 상품(수익성 낮거나 이미 확인한 상품)을 걸러내어 관리 효율**을 높여야 함

현재는 이 과정을 수동으로 하기 때문에 비효율적이고 느림.

---

## 3. 목표 (Goal)

- 포이즌 입찰 정보와 네이버 최저가를 **한 화면에서 비교**할 수 있게 함
- 리스팅 선택 → 가격 분석 → 입찰까지의 과정을 **최소한의 클릭**으로 처리
- **건너뛰기(Skip)** 기능을 통해 관심 없는 상품을 장부에서 숨김 처리하여 업무 집중도 향상
- **최고 수준의 시각적 완성도(Premium Aesthetics)** 확보 및 공간 효율적인 대국 레이아웃 구현
- **입찰 완료 이력**을 즉각적으로 확인하여 중복 입찰 방지

---

## 4. 사용자 워크플로우 (User Flow)

```
[포이즌 API 검색]
    ↓ 품번(Article) 또는 브랜드명으로 조회
[비딩 워크스페이스]
    ↓ 네이버 최저가 및 마진 자동 계산 확인
    ↓ (불필요 상품 발생 시) 'SKIP' 체크하여 목록에서 제외
[상세 분석 및 입찰]
    ↓ 과거 입찰 이력(Indicator) 확인 및 추천가 참고
    ↓ 개별 SKU 단위 또는 다중 선택 후 일괄 입찰(Batch Bid) 실행
[창고 관리]
    ↓ 입찰 성공 여부 및 이력 저장(Supabase)
```

## 5. 핵심 기능 (Core Features)

### 5.1 지능형 대시보드 (Smart Workspace)
- **공간 절약형 헤더**: 마우스 호버 시에만 확장되는 검색 영역을 통해 데이터 가독성 극대화
- **열 너비 유지(Resizable)**: 사용자가 설정한 테이블 컬럼 너비를 브라우저에 저장하여 다음 접속 시에도 유지
- **카테고리 필터링**: 검색 결과 내에서 특정 분류(신발, 의류 등)만 골라보기 지원
- **수익 상품 모아보기**: 네이버 가격 대비 수익이 발생하는 상품만 골라내는 '알짜배기 목록(Flattened View)' 모드 지원

### 5.2 건너뛰기 및 제외 관리 (Skip & Exclude)
- **Skip 체크**: 특정 SKU(옵션)나 SPU(상품)를 건너뛰기 목록에 추가하여 시각적으로 투명하게 처리
- **영구 제외(Exclude)**: 수익성이 극히 낮거나 한국 시장에 맞지 않는 품번은 DB에 영구 등록하여 향후 검색 결과에서 원천 차단
- **저장소 동기화**: Skip 상태는 Supabase DB에 저장되어 기기가 바뀌어도 유지됨

### 5.3 입찰 이력 추적 (Bid History Tracker)
- **입찰 표시기**: 이미 입찰을 진행한 항목은 시계 아이콘(Clock)과 함께 입찰 가격, 날짜를 툴팁으로 즉시 확인 가능
- **중복 작업 방지**: 과거의 실수를 반복하지 않도록 시각적 장치 제공

### 5.4 수익성 분석 및 입찰 실행
- **네이버 최저가 자동 비교**: 품번 검색 시 네이버 쇼핑 API를 통해 실시간 매입가 호출
- **다이나믹 마진 계산**: DB에 설정된 수수료 정책(최소 15,000원, 최대 45,000원 등)을 기반으로 실시간 순수익 산출
- **일괄 입찰(Batch Bid)**: 복수의 SKU를 선택하여 한 번의 클릭으로 대량 입찰 처리

## 7. 설계 및 개발 원칙 (Revised)

### 7.1 Poizon API 안정성 원칙 (Robust API Handling)
- **명칭 준수**: 공식 문서상 `spuIdList` 등 배열 타입 파라미터 명칭을 엄격히 준수하여 `Invalid request parameter` 에러 원천 차단
- **페이지 제한**: 브랜드 대량 검색 시 `pageSize`를 50개 이하로 제한하여 서버 거부 방지
- **낙관적 업데이트**: Skip 처리 등 빈번한 상호작용은 UI를 먼저 변경한 후 서버와 통신하여 쾌적한 반응성 제공

### 7.2 데이터 무결성 (Data Integrity)
- **ID 타입 캐스팅**: `String(id)` 또는 `Number(id)`를 명시하여 데이터 병합 시 발생하는 타입 불일치 방지
- **복구 로직**: 서버 통신 실패 시 변경된 UI 상태를 이전 상태로 되돌리는 자동 복구 로직 포함
